# 仿真结果全 0（Gain=0, GBW=0, PM=0）原因分析

## 1. 现象

用「2.5 倍数 KCL 电流 + 黄金 L/gm_id + 现有表查表 W」跑 `try_nmcnr_table_only.py` 时，得到 Gain=0、GBW=0、PM=0。

## 2. 根本原因：ngspice 模型名未找到

查看 `scene2/sim_NMCNR/log` 可知：

```
Circuit: * leung nmcnr ota ac（从项目根运行）...
Error on line 64 or its substitute:
  m.xx1.xm13.msky130_fd_pr__nfet_01v8 ... sky130_fd_pr__nfet_01v8__model ...
could not find a valid modelname
Simulation interrupted due to error!
```

- **AC 仿真**在解析到 xm13（以及所有使用 `sky130_fd_pr__nfet_01v8` 的 NMOS）时失败。
- 仿真在 DC/AC 分析前就因“找不到有效模型名”而中断，因此不会产生 `AC_results_1.txt`、`Op_1.txt` 等；`read_simulation_results` 读不到数据，只能得到默认 0。

## 3. 技术原因：PDK 模型名与子电路引用不一致

- Sky130 PDK 的 **子电路**（如 `cells/nfet_01v8/.../sky130_fd_pr__nfet_01v8__tt.pm3.spice`）内部 M 器件引用的是 **无后缀** 的模型名：`sky130_fd_pr__nfet_01v8__model`。
- 同一 pm3 文件里只定义了 **带 bin 后缀** 的模型：`sky130_fd_pr__nfet_01v8__model.0`、`.1`、…，**没有** 定义 `sky130_fd_pr__nfet_01v8__model`。
- PMOS 同理：子电路用 `sky130_fd_pr__pfet_01v8_lvt__model`，库中只有 `...__model.0`、`.1` 等。

因此 ngspice 在展开子电路时找不到“无后缀”的 model 名，报错并中断，导致整次仿真失败、结果全 0。

## 4. 已做修改

在 **NMCNR_IDC_pdk.cir** 和 **NMCNR_AC_pdk.cir** 中，在 `.lib` 之后、`.include NMCNR.cir` 之前增加模型别名：

- `scene2/sim_NMCNR/folded_nfet_model_alias.spice`：定义 `sky130_fd_pr__nfet_01v8__model`
- `scene2/sim_NMCNR/folded_pfet_model_alias.spice`：定义 `sky130_fd_pr__pfet_01v8_lvt__model`

这样在展开 PDK 子电路时，ngspice 能解析到正确的 model，仿真可以正常进行；若仍有 DC 不收敛或指标差，再排查偏置/尺寸/查表 W 等。

## 5. 小结

| 项目       | 说明 |
|------------|------|
| 失败位置   | ngspice 在解析网表时（AC 或 IDC 的 run 阶段），报 “could not find a valid modelname” 并中断 |
| 失败原因   | PDK 子电路引用 `*__model`，库中只有 `*__model.0/.1/…`，缺少无后缀模型 |
| 结果表现   | 无 `AC_results_1.txt` 等输出 → 读到的 Gain/GBW/PM 为 0 |
| 修复方式   | 在 IDC/AC bench 中 .include 上述两个 alias 文件 |

修复后请重新运行：

```bash
python scene2/try_nmcnr_table_only.py
```

若仍为全 0，请查看 `scene2/sim_NMCNR/log` 是否有新的报错（如 DC 不收敛、未饱和等），再针对电路偏置或查表 W 继续排查。
